01

DEX 代码加密

对 DEX 文件进行整体加密处理，防止 Java / Kotlin 代码被反编译读取。加固后使用 jadx、apktool 等工具无法获取可读的源码与业务逻辑。

适用场景：核心业务逻辑、接口信息与密钥的保护。
02

代码虚拟化保护（VMP）

支持将关键方法转换为虚拟化指令执行，不再以标准字节码形式存在；提取后也无法还原为原始方法，显著提高逆向分析成本。

适用场景：核心算法、支付与授权校验、登录鉴权、风控逻辑。
03

字符串加密

被保护方法中的字符串以加密形式保存，接口地址、AppKey、密钥、盐值等敏感信息在 DEX 与 SO 反编译结果中均无明文。

适用场景：防止接口与密钥被检索，防止通信规则被逆向。
04

防注入保护（Xposed 模块）

针对 Xposed 等模块注入框架进行防护，模块无法挂载、Hook 不生效，避免应用行为在运行期被外部模块篡改。

适用场景：防止去广告、内购破解、伪造设备信息等违规篡改。
05

签名校验 · 防二次打包

内置签名一致性校验，二次打包、重新签名或注入代码的版本无法正常运行，有效抑制盗版包流通。

适用场景：防止应用被二次打包分发或植入广告、木马。
06

防调试与 Frida 检测

运行时检测 Frida 等动态调试与 Hook 工具，发现调试环境后应用可立即停止运行，防止运行期抓包与逻辑篡改。

适用场景：防止运行期内存分析、抓包与实时逻辑修改。

关于第三方「AI 加固」工具

部分工具以「AI 一键加固」作为卖点，实际防护仍停留在整体加密层面，常见问题集中在以下几点；提交前建议先确认处理方的资质与数据处理方式。

  • 兼容性差：加固后闪退、无法启动或与第三方 SDK 冲突。
  • 强度有限：代码可被静态还原，运行期也容易被 dump 出原始逻辑。
  • 缺少维护：防调试、防注入与签名校验形同虚设，出问题难以获得响应。

加固接口文档

本页的所有操作都通过下面的 HTTP 接口完成。接口地址会自动识别当前访问域名，示例可直接复制调用。

接口地址/api/

加固接口只接受 POST。JSON 接口使用统一信封结构，上传接口使用 multipart/form-data。成功时 code 为 0，失败时 code 非 0 并附带 msg。

请求结构

{"version":"v1","module":"jiagu","method":"precheck","data":{"md5":"YOUR_MD5"}}

响应结构

{"code":0,"msg":"ok","data":{}}
POST上传预检 precheck

上传前判断底包是否可秒传，并返回今日剩余任务额度。

参数 类型 必填 说明
md5 string 必填 32 位文件 MD5（小写十六进制） 
curl -X POST "http://127.0.0.20/api/" \
  -H "Content-Type: application/json" \
  -d '{"version":"v1","module":"jiagu","method":"precheck","data":{"md5":"YOUR_MD5"}}'
{"code":0,"msg":"ok","data":{"md5":"YOUR_MD5","instant_upload":false,"upload_required":true,"existing_task_count":0,"daily_task_count":1,"daily_task_remaining":9}}

instant_upload 为 true 时可跳过文件上传，直接调用 upload 并复用底包。

POST提交加固 upload

提交 APK 与加固参数，创建一条新的加固任务（使用 multipart/form-data）。

参数 类型 必填 说明
file file 必填 APK 文件本体；秒传时可不传
md5 string 必填 32 位文件 MD5（小写十六进制）
encrypt_dex int 可选 是否加密 DEX，1 开启 / 0 关闭，默认 1
encrypt_so int 可选 是否保护 VMP 抽取生成的 SO，1 开启 / 0 关闭，默认 0
so_encrypt_level int 可选 VMP SO 保护强度，1 高强度 / 0 低强度
vmp_rules string 可选 VMP 抽取规则文本，支持 class / extends / implements 与通配符
sign_method int 可选 签名方式，0 自动签名 / 1 自行签名，默认 0
signature_sha256 string 可选 自行签名时必填的 64 位证书 SHA-256
archive_password string 可选 结果压缩包密码，1–20 个字符，默认 123456 
curl -X POST "http://127.0.0.20/api/" \
  -F "version=v1" -F "module=jiagu" -F "method=upload" \
  -F "md5=YOUR_MD5" -F "encrypt_dex=1" -F "encrypt_so=1" -F "so_encrypt_level=1" \
  -F "vmp_rules=class * { onCreate; }" -F "sign_method=0" \
  -F "archive_password=123456" -F "file=@app.apk"
{"code":0,"msg":"ok","data":{"task_id":1024,"md5":"YOUR_MD5","instant_upload":false,"status":0,"status_text":"等待加固"}}

每次调用都会新建一条独立任务，同一底包可用不同参数重复提交；秒传请求不需要上传文件。

新手指引：为什么必须填写 SHA-256？

这里填写的是你准备为最终 APK 签名的证书指纹。星野 Ark 会将它用于签名一致性校验，防止加固结果被其他证书重新签名。

签名不一致会导致应用闪退 下载加固结果后，必须使用与此 SHA-256 对应的同一张证书签名。若换用其他证书，应用可能在启动时因签名校验失败而立即退出。
  1. 使用你常用的 APK 签名工具打开准备签名的应用或证书，并进入“签名信息”。
  2. 找到 SHA256 一项，复制完整的 64 位十六进制字符；不要填写 0x 前缀、冒号或空格。
  3. 将指纹粘贴到上方，下载结果后使用这张证书完成最终签名。
